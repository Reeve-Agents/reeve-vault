# Stripe Projects - Commands

> [!summary] Summary
> - Every Stripe Projects command is `stripe projects <command>`. The plugin installs with `stripe plugin install projects`.
> - Services are addressed as `<provider>/<service>`. Resources can also be addressed by resource name or resource ID (for example `res_abc123`).
> - Global flags for agents and CI: `--json`, `--no-interactive`, `--auto-confirm`, `--quiet`, `--accept-tos`, `--stream`, `--debug`, `-v, --version`.
> - Developer preview: "Commands and flags might change." Check `stripe projects --help` or `stripe projects <command> --help`.
> - Source: https://docs.stripe.com/cli/projects and https://docs.stripe.com/projects

## Project lifecycle

### projects init

- Initializes a Stripe Projects workspace in the current directory.
- Creates project state files, an `AGENTS.md` context document for AI agents, and adds credential paths to `.gitignore` automatically.
- Argument `<project-name>`: optional; defaults to the current directory name.
- Flag `--from <url>`: initialize from a shared stack URL generated by `stripe projects share`. Provisions fresh instances of the same services into a new project. Run in an empty directory.
- Agent bootstrap form: `stripe projects init --yes` (do not use `--json` with `init`).

```sh
stripe projects init my-app
stripe projects init --from https://projects.dev/s/abc123
```

### projects list

- Lists all Stripe projects on your Stripe account: name, ID, creation date. Use the ID with `stripe projects pull`.

```sh
stripe projects list
```

```
NAME           ID                CREATED
my-app         proj_abc123       2026-05-01
staging-env    proj_def456       2026-04-15
```

### projects pull

- Pulls an existing project into a new local directory. Run it from an empty directory.
- Creates `.projects/state.json` and `.projects/state.local.json`, then writes `.env` by running `env --pull`.
- Connects to existing service instances. It does not provision new ones.
- Argument `<project-id>`: get it from `stripe projects list`.

```sh
stripe projects pull proj_abc123
```

### projects status

- Shows project name, Stripe account, associated provider accounts, provisioned resources, current tiers, and health status.
- With named environments, also shows environment membership and marks the active environment for this checkout.

```sh
stripe projects status
```

```
Project:  my-app (proj_abc123)

PROVIDER     SERVICE    TIER      STATUS
vercel       project    hobby     ✓ healthy
supabase     project    free      ✓ healthy
openrouter   api        free      ✓ healthy
```

## Discovery

### projects catalog

- Lists all providers, their service categories, plan tiers, add-ons, and pricing.
- Use it to discover service identifiers and plan names before `stripe projects add`.
- Optional argument: a provider name or a category.

```bash
stripe projects catalog
stripe projects catalog <provider>
stripe projects catalog <category>
stripe projects catalog supabase
stripe projects catalog supabase --json
stripe projects catalog --json
```

### projects search

- Searches the catalog by keyword. Returns matching providers and services.
- Agent skill: if `result_count` is 0, the service was not found.

```bash
stripe projects search <keyword>
stripe projects search database
stripe projects search <query> --json
```

## Manage a service

### projects add

- Provisions a service from a provider into the current project.
- Associates an existing provider account with your Stripe account, or creates one, before adding the service.
- The CLI authenticates with the provider, provisions the resource, saves encrypted credentials to `.projects/vault/vault.json`, and writes environment variables to `.env`.
- Run `stripe projects billing add` before provisioning paid plan tiers.
- Argument `<provider>/<service>`, for example `vercel/project` or `supabase/project`.
- Flag `--config <json>`: provider-specific configuration as a JSON string (plan tiers or provider options in non-interactive mode).
- Flag `--name <name>`: custom resource name (docs example `--name dev-db`; projects.dev lists `--name <n>`).

```bash
stripe projects add <provider>/<service>
stripe projects add vercel/project
```

```sh
# Specific plan tier, non-interactive
stripe projects add amplitude/analytics \
  --config '{"plan_tier":"plus-v3-10k-mtu-monthly"}' \
  --no-interactive \
  --accept-tos

# JSON output
stripe projects add openrouter/api \
  --no-interactive \
  --json \
  --auto-confirm

# Named resource in the active environment
stripe projects add neon/postgres --name dev-db
```

### projects link

- Associates an existing provider account, or creates one, without provisioning a resource.
- Recommended first step in agent-driven workflows: establish provider connections before `add`.
- Recovery for error `PROVIDER_NOT_LINKED`. May open a browser.

```bash
stripe projects link <provider>
stripe projects link vercel
```

### projects remove

- Removes a service from your provider account and local project: deprovisions the resource and removes it from project state.
- Destructive: "It deprovisions and deletes the resource in the provider's system. Back up any data before proceeding. You can't undo this action."
- Does not delete credentials already written to `.env` or `.projects/vault/`. Remove them manually, or run `stripe projects env --pull` to overwrite them with the current set.
- Argument: `<provider>/<service>` or a resource name / resource ID.

```bash
stripe projects remove <provider>/<service>
#or
stripe projects remove <resource_name>

stripe projects remove supabase/project
stripe projects remove res_abc123
```

### projects upgrade

- Upgrades a provisioned service to a higher plan tier. Prompts for a plan and billing confirmation with the payment method on file.
- Run `stripe projects billing add` first if billing is not set up.
- Review current tiers with `status` or the provider dashboard first.

```bash
stripe projects upgrade <provider> | <provider>/<service> | <resource_name>
stripe projects upgrade vercel/project
stripe projects upgrade supabase
```

- Payment flow: see [[Stripe Projects - Billing and Spend Limits]].

### projects open

```bash
stripe projects open <provider>
stripe projects open supabase
stripe projects open vercel
```

- Opens the provider's dashboard in your default browser.

### projects rotate

- Rotates credentials: generates new API keys or secrets at the provider and updates the project vault.
- The docs CLI reference says to run `stripe projects env --pull` afterwards. The main docs page says `env --pull` runs automatically after a rotation.

```bash
stripe projects rotate <provider>/<service>
#or
stripe projects rotate <resource_name>

stripe projects rotate supabase/project
stripe projects rotate res_abc123
```

## Environment variables

### projects env

- `stripe projects env` with no flags or subcommands lists variable names with values redacted.
- `--pull` syncs credentials for the active environment to its configured output file and replenishes the vault.

| Subcommand | Effect |
| --- | --- |
| `env list` | List project environments and mark the active one |
| `env show` | Show the active environment, its output file, and resource membership |
| `env create <name> --output <path>` | Create an environment and make it active |
| `env use <name>` | Switch the active environment for this checkout |
| `env update --name <new-name>` | Rename the active environment |
| `env update --output <path>` | Change the active environment's output file |
| `env delete <name>` | Delete an environment |
| `env add <resource_name>` | Add an existing project resource to the active environment |
| `env remove <resource_name>` | Remove a project resource from the active environment |
| `env add <name> --variable --env-key <ENV_KEY>` | Bind an existing project variable to the active environment |
| `env remove <name> --variable` | Unbind a project variable without deleting it |

| Flag | Effect |
| --- | --- |
| `--pull` | Sync credentials for the active environment to its configured output file |
| `--output <path>` | Output file when creating an environment or changing the active one's output |
| `--name <new-name>` | Rename the active environment |

```sh
stripe projects env
stripe projects env --pull
stripe projects env list
stripe projects env create development --output .env.dev
stripe projects env add dev-db
```

- Full behaviour: [[Stripe Projects - Environments and Credentials]].

### projects variables

```bash
stripe projects variables set <name> --env-key <ENV_KEY> --value <value>
stripe projects variables list
stripe projects variables delete <name>
```

- Omitting `--value` in interactive mode prompts for the value securely.

## Billing and spend

### projects billing

| Subcommand | Effect |
| --- | --- |
| `billing show` | Display the payment method on file |
| `billing add` | Add or update the payment method. Required before provisioning any paid plan tier |
| `billing update` | Set or update global or per-provider monthly spend limits |

| Flag (billing update) | Effect |
| --- | --- |
| `--limit <amount>` | Monthly spend cap in USD. Global unless `--provider` is set |
| `--provider <provider>` | Scope the limit to one provider. Per-provider limits take precedence over the global limit |

```sh
stripe projects billing show
stripe projects billing add
stripe projects billing update
stripe projects billing update --limit 50
stripe projects billing update --limit 20 --provider supabase
```

### projects spend

```bash
stripe projects spend
stripe projects spend --duration 3m
stripe projects spend --since 2026-01-15 --until 2026-03-10
stripe projects spend [provider]
```

```
PROVIDER      THIS MONTH   LAST MONTH
vercel        0.00 USD     0.00 USD
supabase      0.00 USD     0.00 USD
openrouter    1.24 USD     3.87 USD
────────────────────────────────────
TOTAL         1.24 USD     3.87 USD
```

- Flag rules: [[Stripe Projects - Billing and Spend Limits]].

## Sharing and context

### projects share

- Generates a URL that encodes the project's service stack (providers and services only). Credentials and configuration values are never included.
- Run from a project directory with at least one service. The URL is self-contained and does not expire.

```sh
stripe projects share
```

```
Share URL: https://projects.dev/s/abc123
```

- Recreate the stack in an empty directory: `stripe projects init --from <URL>` (provisions fresh instances).

### projects import

- Adds services from a shared stack URL to an already-initialized project. Unlike `init --from`, it merges into the current project without creating a new one.

```sh
stripe projects import <URL>
stripe projects import https://projects.dev/s/abc123
```

### projects llm-context

- Displays and writes a local file that combines your project context with all provider-supplied LLM context files.
- CLI reference: generates `AGENTS.md` with provider documentation, quickstart instructions, and environment variable names, for agents such as Claude, Codex, Gemini, Cursor.

```sh
stripe projects llm-context
```

## Global flags

"Every command supports flags for non-interactive environments such as CI/CD pipelines, scripts, and agents."

| Flag | Description |
| --- | --- |
| `-v, --version` | Show current plugin version |
| `--json` | Return output as structured JSON instead of formatted text |
| `--no-interactive` | Disable interactive prompts and confirmation dialogs. Commands fail when required input is missing |
| `--auto-confirm` | Accept confirmation prompts automatically, for example when you remove a service |
| `--quiet` | Suppress non-essential output and only return final results or errors |
| `--accept-tos` | Accept provider ToS without prompting |
| `--stream` | Enable streaming output animations |
| `--debug` | Enable debug logging for Stripe API requests |

- projects.dev agent tip: `--no-interactive --auto-confirm` runs without user prompts in automated workflows.
- Commands can run from the project root or any nested directory within the project (projects.dev).

## Commands listed on projects.dev only

These appear in https://projects.dev/llms.txt but not on the docs.stripe.com CLI reference pages:

```
stripe projects unlink <provider>               # Disconnect a provider from your project
stripe projects services list                   # List all services in a project
stripe projects downgrade <provider>/<service>  # Downgrade to a lower tier or free plan
stripe projects update <provider>/<service>     # Modify a resource within the same provider
stripe projects switch-account                  # Change active Stripe account
```

- The docs page also uses `stripe projects services list` to find resource names.
- The CreateOS docs use `stripe projects update createos-plan --service <plan>` (see [[CreateOS on Stripe Projects]]).
