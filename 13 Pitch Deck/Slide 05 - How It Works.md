# Slide 05 - How It Works

> [!summary] Purpose
> Show the end-to-end flow in six steps so the audience understands Reeve is a lifecycle, not a chatbot.

## On-slide copy (≤35%)

- Eyebrow: `HOW IT WORKS`
- Headline: **From plain words to proven operations.**
- Six step labels (on the bento cards):
  1. `Describe`: chat, voice, PDF, sheet
  2. `Compile`: rules → tested code
  3. `Simulate`: 60 days in minutes
  4. `Audit`: mutation tests
  5. `Approve`: owner passkey
  6. `Run & maintain`: tested diffs

## Visual (≥65%)

- **Concept:** a **bento grid of 6 cards** (AgenticWebTeam style), each with a **giant faded numeral** (01–06) and a small illustrative UI fragment:
  1. chat bubble + PDF icon
  2. rule card → code snippet
  3. timeline strip (tenants × days)
  4. checklist "12/12 caught" in violet
  5. phone with Face ID prompt
  6. a diff with green/red lines
- A thin lime line connects the cards in order. Cards in `ink` with `white` borders at 10% opacity; the active accents are role colours.
- Small annotation: the rule types `RULE · CONSTRAINT · KPI` along card 2.

## Layout

- Bento grid of 3 × 2 cards, ≈ 75% of the area. Headline in the top band.

## Assets needed

- 6 small UI fragments (reuse from the product mockups)
- Large numerals 01–06 (typeset, 8% opacity)

## Speaker notes

"The owner describes the process in plain language, or uploads an SOP or a spreadsheet. The Builder asks clarifying questions, classifies each statement as a rule to execute, a constraint to guard or a KPI to monitor, and writes it as tested code. It simulates two months in minutes with Stripe test clocks. The Auditor tries to break it. The owner approves with a passkey. From then on it runs, and every change goes through the same loop."
