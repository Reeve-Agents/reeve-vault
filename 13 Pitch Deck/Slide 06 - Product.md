# Slide 06 - Product

> [!summary] Purpose
> Make it real: show the product surfaces. Judges should see agents writing and running code in a sandbox (the "glass box") and the owner approving on a phone.

## On-slide copy (≤35%)

- Eyebrow: `THE PRODUCT`
- Headline: **Watch your agents work. *Approve what matters.***
- Four callout labels pointing at the mockups:
  - `Rulebook`
  - `Simulation`
  - `Agent glass box`
  - `Passkey approval`

## Visual (≥65%)

- **Concept:** a hero composition of **one laptop + one phone**, dark UI:
  - **Laptop:** split view. Left: the **Rulebook** (numbered rule cards with type tags RULE/CONSTRAINT/KPI and status chips draft/audited/approved). Right: the **Agent glass box** live log: code being written, `exec` lines, and a highlighted line `egress blocked: evil.com` in `auditor` violet. Bottom strip: the **Simulation timeline** grid (tenants × days with invoice/reminder/fine dots).
  - **Phone:** an **approval modal**: "Refund Rp1,500,000 to Room 12?", impact summary, Face ID glyph, buttons `Approve` (lime) / `Decline`.
- UI palette: `ink` surfaces, `white` text, `signal` primary, `auditor` for Auditor events, `trust` for receipt IDs.
- Use Mobbin / ScreensDesign references for dashboard, timeline and approval-modal patterns.

## Layout

- Devices take ≈ 75% (right/centre). Headline top-left. Callout labels with thin leader lines.

## Assets needed

- Laptop and phone frames
- UI mockups of the Rulebook, glass box, simulation timeline and approval modal (these can be the real MVP screens later)

## Speaker notes

"This is what the owner sees. The rulebook in plain language. A simulation showing exactly what each tenant will receive. And the glass box: every line of code the agent writes and runs, live, including the attempts we block. Anything touching money comes to the owner's phone as one tap with Face ID."
