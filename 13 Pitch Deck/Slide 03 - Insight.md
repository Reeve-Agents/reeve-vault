# Slide 03 - Insight

> [!summary] Purpose
> Reframe the problem: don't let agents act on money directly. Make them write the code, prove it, and have a second agent check it. Finance's maker-checker principle, applied to AI.

## On-slide copy (≤35%)

- Eyebrow: `THE INSIGHT`
- Headline: **Don't let AI touch the money. *Let it prove the rules.***
  (the second sentence in Instrument Serif Italic, muted)
- Label under the diagram: `Maker-checker, for agents`

## Visual (≥65%)

- **Concept:** a two-lane comparison diagram.
  - **Top lane (crossed out, grey):** `Agent → 💸 Money`. A direct arrow with a broken red line.
  - **Bottom lane (lit):** `Agent writes code` → `Tests + simulation` → `Second agent checks` → `Owner passkey` → `Money moves`. Five nodes; Builder node in `signal`, checker node in `auditor`, passkey node in `white`.
- Background `ink`. The bottom lane glows softly in a lime → violet gradient.

## Layout

- Diagram spans the full width in the middle band (≈ 65%). Headline in the top 30%.

## Assets needed

- Five node icons (code brackets, flask/test, shield-check, key/passkey, coin)

## Speaker notes

"Our insight: the agent shouldn't move money. It should write the logic as code, prove it with a simulation, and then a second, independent agent checks it. Banks have done maker-checker for decades. We apply it to AI agents, with the owner as the final approver."
