## The governed agent runtime

- A governed runtime with a full agent lifecycle: **intent, generate, build, govern, deploy, observe, heal**.
- Self-healing execution (detect, diagnose, patch, redeploy) keeps agents reliable after go-live.
- Built to run on BTP (Kyma), act on BDC data products, and register into the SAP AI Agent Hub over A2A.

## Cited, not generated

- A deterministic core computes and reconciles every figure; the model only narrates over cited findings.
- The runtime is architecturally incapable of inventing a number. That is the direct answer to the liability and auditability gap.

## Complement, never compete

- Not a marketplace: the Agent Hub is. Not a foundation: BTP AI Foundation is. Not orchestration: Joule is.
- CreateOS is the factory and reliability layer that feeds the Hub over A2A and makes the BTP investment more valuable.

## Where CreateOS sits in the SAP Business AI Stack

CreateOS slots into the one layer SAP leaves to partners: execution and reliability. It reads the system of record, it never replaces it.

| Layer | Owned by | Items | CreateOS posture |
| --- | --- | --- | --- |
| Context | SAP | Business Data Cloud, Knowledge Graph, domain models | Agents consume BDC data products as grounded truth. Read, never replicate; the system of record stays untouched. |
| Build | SAP + partners | Joule Studio, Agent Builder, MCP | Full interop over MCP and A2A. Partner-built agents deploy onto CreateOS instead of rebuilding plumbing per project. |
| Governance catalog | SAP | SAP AI Agent Hub, GA Q3 2026 | A2A-compliant. CreateOS agents register into the Hub and run under SAP's discovery, verification, and monetization catalog. |
| Execution and reliability | CreateOS | The open layer, no named SAP capability | Self-healing runtime. RBAC, PII, and policy enforced at runtime. Pilot to production in weeks. Runs across SAP and non-SAP estates, sovereign or multi-cloud. |

## One pattern, not a snowflake

- Example: a manufacturer midway through ECC to S/4HANA. BDC already publishes clean Supplier-Master, Open-PO, and Inventory data products. The pain is acting on them.
- An agent scores every open PO against supplier health and disruption signals, ranks exposure by revenue impact, and drafts replacements: expedite, dual-source, reschedule.
- Weeks, not months, because nobody rebuilds deployment, auth, or metering. SAP keeps the system of record and gains stickier BDC consumption.

| Step | Who | Role |
| --- | --- | --- |
| 01 | SAP | System of record and governed BDC data products. |
| 02 | Joule | The conversation. The buyer asks, Joule routes. |
| 03 | SI / Partner | The agent logic, onboarded with SAP teams. |
| 04 | CreateOS | Runtime, governance, observability, per-use metering. |
